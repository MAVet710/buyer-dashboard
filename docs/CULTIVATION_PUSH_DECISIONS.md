# Continuous cultivation intake: primary decisions

Date: 2026-09-26. Status: implementation contract, not a deployment or hardware-compatibility claim. Base main is 7ff2dc921a69cf82419d4cab8d27ebe50ed7567c (0086). Four read-only research reports are retained in the owner's private cultivation-push-20260926 evidence directory.

1. Preserve Windows FastAPI/Caddy, hosted Supabase auth/data, current UI and canonical EdgeStore. No recurring cloud queue, new DNS, equipment controls, POS, Dutchie Live or automatic Work spam. A receiver acknowledgement is not agronomic health.
2. Implement a first-party normalized HTTP batch receiver under `/api/v1/external/v1/cultivation-telemetry/{connection_id}/batches`. It is not a native Growlink webhook endpoint. Authentication binds exactly one service account, organization, facility and connection; explicit `cultivation:ingest` scope is required. No wildcard-only access, human-session impersonation or caller-controlled room/crop snapshots.
3. Prefer a new scoped ingress-grant relationship using existing hashed ServiceAccount tokens, rather than a new secret store or changes to historic migrations. Migration 0087_cultivation_push follows 0086. File connections remain valid; push is an explicit mode for normalized JSON, not a claim of native vendor discovery. Grant issuance/revocation uses the existing human authorization and audit rules. Tokens are returned once on explicit issuance, never logged or included in ordinary responses.
4. Share the existing bounded historical mapping resolver between human imports and machine admission. Admit only against current valid server authorization; no positive auth cache during control-plane outage. In-flight bounded admissions authorized before revocation may finish; state this boundary honestly. Do not hold SQLite transactions across network requests.
5. Envelope is `{schema_version:1,batch_id:<stable>,readings:[...]}`. At most 500 records and 1 MiB; enforce before unbounded JSON parsing. Stable device/channel/event identity is required. Forbid incoming organization, facility, room, crop, mapping, credentials, URLs and arbitrary metadata. Server receipt clock is authoritative. Values, original units and observation timestamp representations remain intact.
6. Return `200` and `committed:true` only after the local durable commit, echoing batch identity and bounded dispositions. Pending, invalid-quality and conflicting measurements can be durably retained without becoming valid. Structural rejection commits nothing. Retries keep event identity and payload unchanged, including after ambiguous/lost responses. This is at-least-once delivery with deduplication, not exactly-once transport.
7. Use safe fixed 400/401/403/413/415/422 error bodies, 429 with Retry-After for admission pressure, and 503 for unavailable authorization/storage. Never return a success before persistence. Reuse authentication semantics without a Supabase last_used_at write for every packet. No per-sample central observations or second machine ledger.
8. Continuous local collection initially watches operator-approved, atomically published normalized export files into the SAME local EdgeStore. It must run without importing application/ORM or needing Supabase while offline, retain pending evidence for later authorized mapping, and survive restart and replays. No implicit Windows task installation. A remote sender transport queue, if later added, is not an analytics store and cannot claim facility-local raw storage when forwarding outside the facility.
9. Maintenance must be bounded and fair across pending records, dirty rollups, archive acknowledgements and retention. Preserve original snapshots, unknown gaps, independent sensors, exact revision acknowledgements and evidence-protecting retention. Retain explicit quotas and stop without false acknowledgement when full. Fix full-history quota rescans and rollup row-limit behavior before commercial streaming capacity claims.
10. Capacity estimates are assumptions until benchmarked: 50 devices x 6 metrics/minute = 432,000 readings/day. The old 100,000-row quota can fill within 5h33m, sooner under byte limits. No unlimited-retention promise. Expose actual limiting resource, usage, backlog and configured replay/retention horizon; never silently delete unresolved or disputed evidence.
11. Keep transport contact, durable receipt, valid observation freshness, expected sensor coverage and recipe deviation separate. Use 'No zone assigned', not 'Whole room', for missing zone attribution. Do not label an old file or threshold event a live environmental stream.
12. First compatibility target is customer-authorized normalized HTTP/JSON or finalized exports. Native Growlink, MQTT, BACnet and Modbus require reviewed schemas, credentials and exact device/protocol capabilities. Do not invent vendor paths or equate developer-portal availability with production entitlement. No generic write/control methods.
13. Validation must inject commit-before-response loss, network restart, bad timestamps/units/quality, unknown mapping, tenant crossover, revoked/expired grants, oversize/chunked bodies, capacity exhaustion and competing collectors. Use actual service/API/EdgeStore boundaries. Final PC/public acceptance remains mandatory and is not delegated to research.
