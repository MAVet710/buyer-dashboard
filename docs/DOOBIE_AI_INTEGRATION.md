# Doobie AI integration

Buyer Dash uses the DoobieLogic FastAPI v4 service as its only AI provider.
Do not point Buyer Dash at the Doobie Streamlit chat application; the base URL
must serve `GET /health` and `GET /api/v1/auth/check`.

## Buyer Dash secrets

Configure these in Streamlit Cloud under **App settings → Secrets**:

```toml
DOOBIE_BASE_URL = "https://doobie-api.onrender.com"
DOOBIE_SERVICE_API_KEY = "<Buyer Dashboard service key generated by Doobie>"
```

The following legacy aliases remain accepted during migration:

- `DOOBIE_AI_BASE_URL` or `DOOBIELOGIC_URL`
- `DOOBIE_API_KEY` or `DOOBIELOGIC_API_KEY`

Never store the raw service key in Git, documentation, screenshots, support
messages, or browser-visible diagnostics. `DOOBIE_ADMIN_API_KEY` belongs only to
Doobie administration and must not be used for normal Buyer Dash requests.

## Doobie service configuration

The Doobie FastAPI deployment should configure:

```text
DOOBIE_API_KEY=<same service key used by Buyer Dash>
DATABASE_URL=<persistent Postgres connection>
DOOBIE_BACKEND_MODE=postgres
DOOBIE_STRICT_CONFIG=true
DOOBIE_AI_PROVIDER=groq
GROQ_API_KEY=<provider secret>
DOOBIE_GROQ_MODEL=openai/gpt-oss-120b
```

Groq is the current free-first conversational provider. If it is unavailable,
Doobie returns its deterministic rules and grounding response instead of
silently switching Buyer Dash to another model provider.

## API coverage used by Buyer Dash

- `GET /health`
- `GET /api/v1/auth/check`
- `GET /api/v1/knowledge/modules`
- `GET /api/v1/knowledge/professional-domains`
- `GET /api/v1/compliance/jurisdictions`
- `POST /api/v1/support/buyer_brief`
- `POST /api/v1/support/inventory_check`
- `POST /api/v1/support/extraction_brief`
- `POST /api/v1/support/ops_brief`
- `POST /api/v1/support/copilot`
- `POST /buyer/intelligence`
- `POST /extraction/intelligence`
- `POST /learning/feedback`
- `GET /learning/summary`
- `POST /api/v1/license/validate`

Buyer Dash sends both `Authorization: Bearer <key>` and `x-api-key: <key>` for
compatibility with generated service keys and environment-based service auth.

## Connection verification

LEVEL DEV users can open **Data & Integrations → AI & METRC Integrations** and
select **Test Connection**. A successful test displays:

- Doobie API version
- detected knowledge-module count
- professional-domain count
- jurisdiction count
- conversational provider and model
- deployed Doobie build version

The API key is always masked after saving.
