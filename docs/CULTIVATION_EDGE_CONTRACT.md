# Local cultivation evidence contract

Status: bounded implementation contract, 2026-09-26. Integration and release belong to the primary integrator.

## Callable API

`Scope(organization_id: str, facility_id: str, connection_id: str)` is immutable. Every collector operation requires the complete scope. The backend authorizes these IDs before calling this local library.

`EdgeStore(path, *, max_scope_rows=100000, max_scope_bytes=134217728, max_disk_bytes=536870912, max_batch=500, max_query_rows=10000, max_gap_seconds=300, bucket_seconds=3600, max_window_seconds=2678400, busy_timeout_ms=5000)` creates a SQLite WAL store with FULL synchronous commits. No network, ORM, cloud client, credentials or automatic worker is used.

* `ingest(scope, readings, resolved=None) -> dict`: readings are measurement dictionaries. `resolved` is either None or a list of immutable mapping dictionaries aligned with readings. Returns `{accepted, duplicates, conflicts, quarantined, pending, items:[{identity,status,reason}], committed:true}` only after commit. A quota or batch error raises `EdgeBackpressure` and rolls back the whole batch. A caller may advance its import cursor only after this return.
* `retry_pending(scope, resolver, limit=100) -> dict`: resolver receives `(scope, raw_reading)` and returns a snapshot or None. Rechecks pending and mapping-validation quarantine rows under a write transaction, so concurrent replay cannot overwrite a resolved snapshot. Returns `{resolved,pending,examined,truncated}`. Exceptions leave the transaction uncommitted. Resolver must be local, deterministic, bounded and must not perform network IO. Invalid quality, unsafe metadata, disputes and missing source identity are not silently repaired by mapping replay.
* `evidence(scope, limit=100, after='') -> dict`: local administrative evidence page, `{items,next,truncated}`. Never expose this raw endpoint to cloud synchronization. IDs are opaque strings scoped to a connection.
* `diagnostics(scope) -> dict`: `{counts,scope_rows,scope_bytes,limits,raw_stays_local:true,last_received_at,last_valid_observed_at}`. Timestamps are UTC ISO strings or null, aggregated only within the exact organization/facility/connection scope. `last_received_at` is the latest local first-persistence receipt clock across all evidence states, never a supplied provider receipt timestamp. Bad and pending evidence advance it; exact duplicate retries do not. `last_valid_observed_at` is the greatest observation timestamp among currently ready or archived evidence with validated measurement and resolved mapping. Pending, quarantine and disputes do not qualify; a later dispute can remove a previously qualifying timestamp. Retention preserves both clocks. Neither field asserts connected/live, expected cadence, current data freshness or agronomic health. Contains no local paths, raw values, provider bodies or exception text.
* `rollup(scope, start, end) -> dict`: UTC epoch-aligned bucket boundaries, bounded window. Rebuilds missing/dirty buckets atomically from local evidence. Returns `{rebuilt,unchanged,blocked,truncated}`. Truncated queries publish no partial aggregates. Aggregate revisions change only when content changes. Late readings dirty all intersecting hold buckets, including neighboring buckets.
* `room_summary(org, facility, room, start, end, cycle_id=None, targets=None) -> dict`: reads persisted clean rollups, with explicit facility-wide connection scope. UTC aligned bounded window. Returns `{status,streams,truncated,start,end}`. Each stream is separate by source stream and semantic context as defined below. No independent sensors are summed. `targets` must be None: historical targets come from validated snapshots. Missing buckets yield UNKNOWN seconds. No raw query or provider request occurs.
* `pending_aggregates(scope, limit=100) -> dict`: `{items,truncated}` with aggregate-only `{key,revision,payload}` records. Concurrent publishers can receive the same revision; the receiver must deduplicate by scope/key/revision and update its current pointer only when the revision generation increases. Revision format is a zero-padded 20-digit generation, a colon, and a SHA-256 content hash. This prevents stale deliveries overwriting newer aggregates. There is deliberately no raw drain.
* `ack_aggregate(scope, key, revision) -> bool`: acknowledges only that exact clean current revision after durable receiver acceptance. No numeric or unscoped acknowledgement exists. Duplicate acknowledgement is idempotent; stale or wrong-scope acknowledgement returns false.
* `retention(scope, before, limit=100) -> dict`: `{purged,protected,truncated}`. Purges only raw bodies of ready records older than the cutoff whose entire possible hold horizon has clean acknowledged rollups. Preserves identity/fingerprint tombstones and aggregate evidence. Pending, quarantined, disputed, unaggregated and unacknowledged evidence is protected. Late evidence overlapping purged buckets is quarantined for explicit reconciliation; incomplete raw history is never used for a replacement aggregate.

## Reading and resolved snapshot

Reading fields: `event_id`, `source_device_id`, `source_channel`, `source_metric`, `value`, `unit`, `observed_at`, optional `received_at`, `quality` (default `valid`). JSON/CSV adapters require explicit column names and explicit source metric/unit/channel mappings. Value, source unit, metric/channel, timestamp text and first receipt timestamp are retained before normalization. NaN/infinity are stored as invalid string evidence. Missing identity is assigned a quarantine-only opaque ID; it never becomes a publishable sample. Identity is the hash of scope, source device, channel and event ID, never payload or room. A changed measurement under that identity is a dispute, not a second accepted reading. Retry receipt time is excluded from the fingerprint.

Snapshot required fields: `organization_id`, `facility_id`, `connection_id`, `room_id`, `device_id`, `sensor_id`, `mapping_revision`, `metric`, `effective_from`, `effective_to`. Optional fields: `zone_id`, `cycle_id`, `stage_id`, `recipe_revision`, `target_min`, `target_max`, `threshold_seconds`. The effective half-open interval must include the observation and must end at the earliest mapping, room occupancy, cycle, stage or recipe boundary. All relationship validation and approved recipe selection belong to the backend. Scope equality and interval validity are checked locally. Snapshots are copied, persisted and never replaced by retries. Targets require a recipe revision; none are invented.

Arbitrary metadata, raw references, provider bodies, URLs and credentials are not accepted persistence fields. Unexpected reading metadata is discarded and the measurement quarantined. Identifiers are bounded tokens; invalid sensitive text is replaced by a fixed rejection marker. Exceptions and diagnostics use fixed codes.

## Aggregation and limits

Each continuous stream uses last-observation-held intervals capped by `max_gap_seconds`, the next evidence timestamp (including invalid or pending evidence), the individual immutable snapshot effective end and the bucket end. Its start is clipped by the observation, individual effective start and bucket start. A next valid reading with different semantic context additionally clips the previous hold at its effective start, even when that boundary was learned after the previous reading. Bounded lookahead of one maximum gap makes separate bucket rebuild calls agree with a combined call. No interpolation crosses invalid quality or context boundaries. Output contains sample count/mean, separate time weighted mean, coverage/unknown seconds, above/below/in-target seconds, and threshold-qualified deviation intervals. PPFD integration is reported as measured DLI contribution with partial coverage, never extrapolated to a day. Event, volume and duration metrics have distinct totals, not averages. State metrics have observed active seconds, not an invented average. Missing coverage is UNKNOWN.

Scope quotas count all retained evidence/tombstones and aggregate rows and their serialized bytes plus conservative per-row overhead. The shared physical file/WAL ceiling is additional backpressure, not a claim of exact per-tenant SQLite page allocation. Transactions and reads are bounded; exceeding limits returns explicit truncation or rolls back, never silently drops samples. Tombstones and aggregates are intentionally not automatically expired, so eventual capacity requires an operator storage/archive decision. Filesystem permissions, disk encryption, authorized scope construction and database backup are host/integrator responsibilities.

Rollup calls allow at most `max_batch` buckets and `max_query_rows` evidence rows, including predecessor lookback and successor lookahead of one maximum gap. Split larger ranges into aligned windows and honor `truncated`. Each aggregate, aggregate-outbox page and room-summary read is capped at 8 MiB of serialized aggregate payload. Room summaries also cap the number of returned streams. Default rollup interval is one UTC hour. Bucket width and maximum hold gap are pinned in the store configuration; opening an existing store with different values fails closed. Retention is configured by its explicit cutoff, and protects neighboring raw evidence when unresolved samples could require a future bucket rebuild. Purge removes original and normalized per-sample values, retaining identity hashes and mapping snapshots.

An aggregate payload is `{start:<UTC epoch seconds>,end:<UTC epoch seconds>,calculation_version:2,streams:{<opaque stream hash>:<statistics>}}`. Statistics contain `stream:[source_device_id,source_channel]`, stable context `snapshot`, `metric`, canonical `unit`, registry `kind`, `sample_count`, `sample_sum`, `integral`, `coverage_seconds`, `above_seconds`, `below_seconds`, `in_target_seconds`, `total`, `active_seconds`, merged excursion `intervals:[[start,end,direction],...]`, and `attribution_intervals:[[start,end],...]`. All aggregate interval bounds are UTC epoch seconds. These are aggregation sufficient statistics, not raw samples. Sender/receiver must validate the complete scope in every snapshot against the authenticated outbox scope.

Version 2 group identity hashes the source stream plus all non-null snapshot fields except `effective_from` and `effective_to`. Scope, actual mapped device and sensor, room, zone, cycle, stage, mapping revision, metric, recipe revision, approved target bounds and threshold semantics remain part of identity. Missing and null optional fields are equivalent. Different per-reading effective boundaries alone never split a group. Original full snapshots remain unchanged in raw evidence. Aggregate and summary `snapshot` deliberately omit both effective bounds: they describe a semantic context, not one continuous assignment interval.

`attribution_intervals` are sorted, disjoint, half-open intervals of proven held coverage, clipped to the bucket or requested summary window. Only exactly touching intervals merge, including across bucket boundaries. They never union full mapping validity ranges or bridge invalid, pending, expired-hold or context gaps. Their total duration equals `coverage_seconds`. Event/volume/duration samples have empty attribution intervals and zero elapsed coverage. Sample counts and means use valid observations timestamped inside the requested window, while weighted means use held coverage, including valid predecessor evidence. Summary `unknown_seconds = window_seconds - coverage_seconds` uses the entire requested window separately for each contextual sensor stream. Do not sum these unknown denominators across contexts or independent sensors; they are not room occupancy durations. Band seconds are subsets of coverage and do not imply approved targets existed for uncovered time.

Opening an existing local store marks version-1 buckets dirty and clears their acknowledgements. Unpurged buckets rebuild with version 2 while retaining monotonic revision generations. Version-1 buckets whose raw evidence was purged remain blocked for explicit reconciliation; they cannot be published, acknowledged, or shown as clean summaries. This changes no SQLite table schema and no Supabase schema. Receivers must understand the version-2 snapshot and interval shape before publication. Boundary changes without any new resolved evidence cannot be inferred by the edge store; backend review/reconciliation remains necessary.

Numeric values must be finite, non-boolean, within registry bounds and within an absolute computational ceiling of `1e100` to keep bounded sums and integrals finite. That ceiling is not an agronomic target. SQLite secure deletion is enabled, but retention is logical deletion; encrypted backups, filesystem snapshots and durable physical media erasure remain host responsibilities.

Room summary streams replace internal sums/integrals/intervals with `sample_mean`, `time_weighted_mean`, `unknown_seconds`, `status`, typed `total_kind`, and threshold-qualified `deviations:[{start,end,direction,seconds}]`. Continuous measurements have null totals. Event/volume/duration records have null averages and UNKNOWN elapsed coverage because event receipt does not prove continuous collection. Status describes observed coverage, never agronomic health or expected device inventory. Missing streams are not manufactured. With no streams the room status is UNKNOWN for the entire requested window. PPFD includes `measured_light_integral_mol_m2`; `measured_dli_contribution` is populated only for a window contained in one UTC day, with `dli_partial` and `dli_status`. A multi-day light integral is never mislabeled as a daily integral.

## Offline runner and integration handoff

`python scripts/run_cultivation_edge.py --database <local-db> --organization <id> --facility <id> --connection <id> --input <export> --contract <columns-and-metric-mappings.json> --format json|csv` performs one bounded import and exits. It imports standalone edge modules without application initialization, ORM or cloud configuration. It emits only counts and a committed flag. All otherwise-valid offline readings remain pending until the backend supplies historical relationship validation through `retry_pending`; a column/metric hint cannot authorize room or cycle attribution. Repeating the same export deduplicates committed identities. There is no scheduler installation or listener.

The backend owner must wire deterministic permission checks, effective historical snapshot resolution, explicit unmapped-channel review, periodic bounded rollup and retention invocations, aggregate-only optional publishing, generation-aware receiver deduplication and exact revision acknowledgement. A resolver receives raw source metric/channel/unit and must use approved explicit mappings. Do not reuse the old numeric-ID spool acknowledgement or mark a connection connected from fixture validation. The application package initializer may still import ORM modules; standalone use must follow the runner's import path until the package owner provides a lightweight package entry point.

## Bounded current readings

`EdgeStore.latest(org, facility, room, *, now=None, limit=200) -> dict` returns `{as_of, readings, truncated, status}`. Trusted server context supplies all three scope tokens. `now` is an aware datetime or ISO timestamp, defaulting to the local UTC clock. `limit` is an integer from 1 through 200. `status` is always `UNKNOWN`: observed streams alone cannot establish expected room sensor coverage or overall health.

Each reading contains `connection_id`, `source_device_id`, `source_channel`, `device_id`, `sensor_id`, `metric`, canonical `value`/`unit`, `original_value`/`original_unit`, `observed_at`, actual local `received_at`, `data_age_seconds`, signed `latency_seconds`, `quality`, persisted `state`, fixed `reason`, `freshness`, `status`, and an allowlisted immutable `snapshot` (including approved target, recipe revision, stage and cycle IDs where known). Unavailable values are null. No arbitrary metadata or provider receipt claim is returned. Freshness is independently `fresh`, `stale`, or `unknown` per stream, using the store's maximum hold gap. Reading status is `unavailable`, `invalid`, `stale`, `unconfigured`, `above`, `below`, or `in_target`; it never asserts a duration-qualified alert. Expired snapshot context is unavailable. Missing targets are unconfigured.

An indexed exact organization/facility/room query reads at most `max_query_rows + 1` candidates, ordered by observation time (local receipt only for absent observation), identity and fingerprint, descending. Deduplication preserves independent connection, source device/channel and mapped device/sensor/metric. It returns at most `limit` streams. Candidate or stream overflow sets `truncated=true`, including when old or unseen streams may have been excluded. Invalid, disputed, future-quarantined and archived mapped evidence participates in selection and cannot fall back to older healthy evidence. Future evidence stays invalid even after its clock time passes. Evidence without a validated immutable room snapshot cannot be attributed and is omitted, another reason room status remains UNKNOWN. The index is created locally when the store opens, including existing rows; routine latest reads do not rebuild rollups, perform provider/cloud IO, acknowledge or retain evidence.

## Primary integration hardening: calculation version 3

The integrated calculation format is version 3. Version 1/2 buckets are marked dirty for bounded rebuild; purged old-format buckets stay blocked for reconciliation rather than being recomputed from missing raw evidence. Immutable raw snapshots are unchanged.

Summary streams add `sample_minimum` and `sample_maximum`, derived only from actual valid samples inside the requested buckets, distinct from elapsed-time coverage. `outside_intervals` retains all measured above/below episodes. `deviations` contains only continuous episodes satisfying an explicitly configured positive `threshold_seconds` in the approved snapshot. An absent threshold returns `alert_threshold_status: not_configured`, an empty qualified-deviation list, and still preserves above/below durations and outside intervals. No automatic alerts or Work are created.

## Final bounded repair: local durable receiver and threshold semantics

`EdgeStore.archive_aggregates(scope: Scope, archive_dir: Path | str, limit=100) -> dict` is the protected-backend integration seam. The result is `{archived,acknowledged,stale,truncated}`. `archived` counts verified durable acceptances, including identical replay; `acknowledged` counts exact still-current clean revisions acknowledged in SQLite; `stale` counts accepted revisions that could no longer be acknowledged. Limit uses the existing 1..max_batch bound and the outbox's 8 MiB aggregate page ceiling. Calls are explicit and synchronous, with no scheduler, listener, provider request or cloud publication. There is no raw archive endpoint.

The integrator must supply a pre-created, absolute, host-owned local archive directory from protected configuration, never a request path. Full three-part scope must be authorized before calling. The receiver rejects relative paths, parent traversal, UNC paths, symlinks, Windows reparse points/junctions, nonregular artifacts and multiply linked files. Every existing path component is checked. Host ACLs must prevent untrusted processes from changing directory components or artifacts while the receiver runs; path inspection is not a substitute for filesystem access control. No local paths or OS exception text appear in returned diagnostics.

`aggregate_archive.accept_aggregate(scope: Scope, archive_dir: Path | str, item: dict) -> None` accepts one `{key,revision,payload}` envelope without changing any edge acknowledgement. It validates scope and every snapshot, allowed aggregate-only fields, metric/unit/kind, stream identity, interval bounds, revision generation and payload hash, and the scope/bucket-derived key. It accepts current calculation version 3 with the unchanged version-2 stable context grouping. No raw readings, provider metadata, credentials or financial records are serialized.

Artifacts use `<archive-root>/<SHA256(canonical scope)>/<aggregate-key>/<20-digit generation>.json`. Canonical JSON contains `{scope,key,revision,payload}`, including the full generation/hash revision. A generation has one immutable slot: identical bytes are idempotent success, while a different hash/content claiming the same generation or any corrupt artifact fails closed. There is deliberately no latest pointer. Replaying an older revision cannot replace a newer file. A process-level OS lock serializes receiver publication and releases on exit/crash; lock contention fails closed and may be retried explicitly.

New artifacts use exclusive temporary files, flush and fsync, atomic replacement, then exact bounded verified readback and file fsync. POSIX additionally fsyncs directories; Windows uses write-through MoveFileEx for publication. Only after this returns does the store attempt its existing transactionally guarded exact revision acknowledgement. Concurrent dirtying or a changed rebuilt revision prevents acknowledgement. A crash between acceptance and acknowledgement is recoverable by identical replay after restart. Failures raise fixed `EdgeError` codes: `archive_invalid_aggregate`, `archive_unsafe_path`, `archive_artifact_conflict`, `archive_readback_failed`, or `archive_storage_unavailable`. Scope/limit validation keeps its existing fixed codes. A failed multi-item call can have already durably accepted and acknowledged earlier items; retry is idempotent and does not fabricate a batch-wide success.

Retention remains a separate `retention(scope, before, limit=100)` call. Archival does not itself purge anything or advance diagnostic clocks. Existing cutoff, bounded-page, full hold-horizon, pending/quarantine/dispute, dirty and acknowledgement checks remain mandatory. Eligible raw values can be purged only after actual acceptance; identity/fingerprint tombstones still reject duplicates and late evidence touching purged history remains quarantined. SQLite scope quotas and physical store backpressure remain unchanged. Archive revisions and tombstones are not automatically expired. Archive filesystem capacity, ACLs, backup and continued preservation after acknowledgement are host responsibilities; retention trusts the durable acknowledgement and does not rescan archive media for subsequent external tampering or device failure. Physical media erasure is not promised.

Backend audit events should record only authorized scope, action and counts through the existing audit boundary, never archive paths or copied raw bodies. This library neither impersonates an authenticated actor nor creates a competing audit ledger. API exposure, host configuration and release remain the primary integrator's work. No CLI changes were required.

Every summary stream now includes `threshold_semantics:"continuous_same_direction"` and `alert_threshold_status:"configured"|"not_configured"`. Missing or null threshold means not configured; only positive finite numeric thresholds qualify episodes. Band durations and outside intervals remain visible. Adjacent same-direction intervals may join across hours within one stable semantic context. Gaps, direction changes, recipe/stage or other semantic-context changes break continuity; disconnected durations never accumulate into an alert. Existing approved thresholds and immutable snapshots are preserved without agronomic defaults.
