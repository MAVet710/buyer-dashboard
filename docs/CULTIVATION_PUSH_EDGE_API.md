# Local edge integration contract

`EdgeStore.ingest(scope, readings, resolved=None, transport=None)` preserves the existing API. Only an authenticated backend may supply `transport`, an exact dictionary with `batch_id` and `grant_id`, each a safe bounded token (1–160 characters). Local file collection never supplies transport. Invalid transport rejects the entire call before persistence.

`EdgeStore.transport_status(scope)` returns exactly `last_committed_at`, `last_batch_id`, `accepted_total`, `duplicate_total`, `pending_total`, `quarantined_total`, `conflict_total`. Initially the two last fields are null and counters zero. Counters are cumulative committed dispositions, not current evidence-state counts. One row per scope retains last grant internally, never a batch ledger or source body. Updates share the evidence transaction; rollback advances nothing. Duplicate packets advance transport contact and duplicate counts but do not change observation freshness. Receipt/contact is not device health or valid observation time.

## Collection

`FileCollector(store, scope, directory, adapter, format='json', ...)` takes an explicit absolute, host-owned local directory. The store is the same configured canonical EdgeStore; no separate raw/analytics store is created. Do not expose this configuration to equipment or HTTP callers. The host must protect directory/store ACLs and provision the directory. No ACL modification, discovery, network read, scheduler, task, equipment command or archive/delete operation is performed.

Producers must finish, fsync and close each temporary export, then atomically rename it within the directory to `*.ready.json` or `*.ready.csv`. Each file is one bounded batch (default adapter: 500 rows, 2 MiB). Only the configured format is recognized. Columns and each metric/unit/channel tuple must match the explicit adapter contract; extra metadata and duplicate JSON keys are rejected. Original identity/value/unit/timestamp representations are retained. Valid identities with invalid measurements retain normal EdgeStore dispositions. Missing/unsafe identities and structurally invalid files receive one durable diagnostic hold keyed by filename hash and stat signature; they do not create random quarantine rows on every retry. Corrected file contents must be explicitly republished. Held decisions also include the parsing-contract fingerprint, so correcting a registered metric contract permits a bounded retry of an unchanged held source. Committed sources are not reinterpreted by later contract changes. Holds contain no source body or filename.

No symlinks, reparse points, hardlinked files, UNC inputs or parent traversal are accepted. On Windows, final handle paths are verified and source handles deny writes and deletion while reading/committing. Handle identity and size/time checks detect changed files. This depends on the host-owned directory and producer publication contract, not a promise of safety in a directory controlled by an adversarial administrator. Arbitrary direct writes to `.ready` files violate the contract; on Windows an open writer prevents collection.

Defaults scan at most 100 directory entries and process at most 10 files per iteration. An open directory iterator progresses across iterations without loading the directory into memory. A restart rescans from the beginning, skipping committed/held signatures; repeated restarts before a full directory traversal can delay later files. The per-input/store/scope OS lock survives no process crash: the OS releases it automatically, and the harmless lock file remains. No original file is automatically modified or deleted.

The bounded manifest (10,000 distinct filenames per collector by default) resides in the same SQLite database, with only hash/signature/state/reason. Manifest capacity refuses new files before raw ingest. Successful `ingest()` commits before the manifest advances. A crash between those commits replays unchanged original event IDs and deduplicates; a failed raw commit leaves the source unacknowledged. `committed_files` means raw evidence and local manifest completion, not cloud attribution or transport push. Offline capture is pending until backend historical mapping is validated. `transport_status()` stays untouched by local files.

`run(once=False, max_iterations=None, stop=None, report=None)` retries transient storage/open failures using exponential backoff with jitter, capped at 60 seconds by default (configurable to at most 300). Stop events interrupt polling/backoff; between files, a stop is honored. An in-flight file finishes or rolls back with bounded row/byte work and SQLite busy timeout (default five seconds per database operation); an unresponsive OS/disk has no hard wall-clock completion guarantee. Terminal invalid files are held visibly rather than retried indefinitely. Full capacity keeps the original backlog and advances no false acknowledgement.

CLI retains legacy one-file import. For directories, `--once` performs one bounded pass; `--watch` polls; `--max-iterations N` bounds a watch run. `--max-scan`, `--max-files` and `--poll-seconds` configure work/poll bounds. SIGINT/SIGTERM request graceful stop. CLI emits count-only JSON, imports neither application/ORM nor cloud configuration, and installs no persistent execution. A host-provisioned command example is:

```
python scripts/run_cultivation_edge.py --database C:\facility\edge.db --organization ORG --facility FACILITY --connection CONNECTION --input C:\facility\exports --contract C:\facility\contract.json --format json --watch
```

## Maintenance, accounting and bounds

`_usage()` is an indexed counter lookup. On the first schema upgrade only, reconciliation counts all existing evidence and buckets using exactly the legacy byte accounting formula. SQLite triggers cover insert/update/delete, including mapping retry, dispute changes, rollup replacement, archive acknowledgement, retention and transaction rollback. The counters include tombstones and aggregates. These are accounting bytes, not measured filesystem bytes. Fixed per-scope transport/maintenance/capacity metadata and bounded collector manifests are constrained by the existing physical database/WAL reservation, not added to the legacy evidence/bucket accounting formula.

`retry_pending()` and `retention()` persist per-scope composite identity/fingerprint cursors. Protected rows advance the examination cursor without being purged, and exhausted cursors wrap. Retry resolvers run outside SQLite transactions; state/snapshot/reason are rechecked under the write lock before applying a resolved result. Concurrent workers may repeat a page safely. Existing unknown-gap, dispute, snapshot and exact aggregate-ack retention gates remain.

Rollup now preflights at most `max_rollup_rows + 1` indexed source rows (default 100,000 per requested window), with at most `max_rollup_streams` source streams (default 1,000, also constrained by `max_query_rows`). `max_query_rows` still bounds each individual stream's source rows across the requested window and aggregate output groups; it is not silently increased. Each stream is processed with its original predecessor/lookahead and half-open historical snapshots. Work includes each bucket's boundary halo, so repeated bucket calculations can revisit bounded source rows. Aggregate memory remains capped by the existing 8 MiB artifact limit, plus one bounded stream's calculation. The entire requested rollup writes in one transaction; a limit/backpressure failure publishes no partial aggregate. API result queries retain their existing bounds. One stream with more than `max_query_rows` observations in the requested window still requires a narrower aligned window or a separately reviewed work-budget change.

Diagnostics retain prior fields and add `capacity`: measured physical bytes, disk reservation, scoped row/byte headroom, reservation headroom, limiting resource, `available|warning|critical|full`, replay policy and corrective action. Warning begins at 70%, critical at 90%, full at 100%. Projection defaults to unknown. Only at least one hour and 100 net new rows of committed receipt-accounting growth, with a receipt within the last hour and positive byte growth, yields `observed_receipt_growth_scope_only`; this is a historical average, not expected sensor cadence or a physical-disk forecast. A scoped estimate below 48 hours also warns. Duplication does not create apparent growth. Retention, changed workloads, burst imports, disk overhead and future outages can invalidate extrapolation.

No stable vendor identity/tombstone is silently expired. Indefinite operation is **not** established: row/byte/disk quotas, aggregate/archive revisions and the filename manifest eventually need operator capacity management. Safely retiring arbitrary vendor IDs requires an enforceable replay/epoch/contiguous-sequence protocol or retained indexed identity partitions; neither is implemented. Defaults remain 100,000 accounting rows, 128 MiB scoped accounting and 512 MiB physical reservation. The 50-device × six-readings/minute arithmetic is 432,000 rows/day, so the default row quota alone is less than six hours, and bytes can limit earlier. Archive retention never implies permission to erase unresolved/disputed evidence or source files.

WAL and FULL are verified per connection. FULL protects acknowledged SQLite transactions subject to honest filesystem/device behavior; it cannot acquire readings while the facility PC is powered off. Missing acquisition intervals remain unknown. No runtime upgrade was performed. Primary owns integration and release; this document makes no release or commercial-scale claim.
